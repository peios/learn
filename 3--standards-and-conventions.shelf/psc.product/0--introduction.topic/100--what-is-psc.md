**Peios Standards and Conventions (PSC)** is the home for all standards and
conventions used across Peios and its satellite projects. It gives
contributors a shared reference for how to develop, maintain, and document
these projects, whether they are working on the operating system or on a
project that supports it.

## What PSC covers

PSC brings related standards together by subject:

- **PSC Git** defines how projects use Git for version control, including
  branching and how changes are prepared, reviewed, and integrated.
- **Code standards** define shared coding practices and conventions, with
  guidance for individual languages and projects where needed.
- **Documentation conventions** define how documentation is organized,
  written, and maintained, including writing style and the structure of
  specifications and technical reference manuals.

These subjects share one home so contributors can find the conventions
that apply to their work across project boundaries.

## Find a standard

Start with [Using Git](~psc/development-model) for the development model,
[Work Branches](~psc/work-branches) for task branches, and
[Commit Style](~psc/commit-style) for commit messages.

The technical writing and documentation guidance includes:

- [Documentation overview](~psc/overview): the forms of Peios documentation
  and the purpose of each one.
- [Core Style](~psc/core-style): the writing rules shared by every form.
- [Conventions for Specifications and TRMs](~psc/conventions): how to
  structure and write specifications and technical reference manuals.

For code, start with [Coding Style](~psc/scope-and-precedence), then read
the [common formatting rules](~psc/common-coding-rules/formatting) and the
[language profiles](~psc/language-conventions). The guide also covers
engineering practices and tests.
