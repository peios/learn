`cp` copies files and directories.

```
cp [options] source dest
cp [options] source... directory
cp [options] -t directory source...
```

In the first form, `cp` copies one `source` to one `dest`. In the other two, it copies any number of sources *into* a directory, keeping their names.

```
$ cp report.txt report-backup.txt
$ cp report.txt notes.txt /home/jack/archive/
```

## Copying directories

`cp` refuses to copy a directory unless you ask it to descend into one:

| Option | Effect |
|---|---|
| `-r`, `-R`, `--recursive` | Copy directories, and everything inside them, recursively. |
| `-a`, `--archive` | Copy recursively, follow no symbolic links, and request all supported preservation attributes listed below. Equivalent to `-d -R --preserve-all`. |

`-a` requests the tree structure and the supported preservation set, including owner, DACL, SACL, timestamps, hard links, executable-ness, and extended attributes. It does not guarantee a complete security-descriptor duplicate; see the component limits below. A plain `-r` copies the *contents* but gives newly created files fresh security of their own.

A recursive copy never follows a symbolic link *inside the destination*. If a directory being copied corresponds to an entry in the destination tree that is a symbolic link to a directory, `cp` refuses with "cannot overwrite non-directory with directory" rather than writing the source tree through the link. Naming a symbolic link to a directory as the destination operand itself is still allowed, as it is with GNU `cp`.

## What a copy's security descriptor is

This is the part of `cp` that is specific to Peios, so it is worth being precise.

Every file carries a [security descriptor](~peios/security-descriptors/overview) — the record of who owns it and who may do what to it. When `cp` creates a *new* destination file, that new file needs a descriptor. The defaults here describe newly created files, not a promise to replace the descriptor of an existing destination.

**By default, a copy gets a fresh descriptor — it does not inherit the source's.** Specifically, a plain `cp`:

- gives the copy a descriptor **inherited from the destination directory**, exactly as if you had created a new file there;
- makes **you** the owner of the copy;
- gives the copy **fresh timestamps** — the copy's modification time is "now".

This is usually what you want. A file copied into your home directory should be governed by your home directory's rules and owned by you, regardless of where it came from. But when you need the copy to keep something from the source, you ask for it explicitly — with the `--preserve` family.

### The `--preserve` family

`--preserve` carries chosen attributes from the source onto the copy. The attributes you can preserve:

| Attribute | What it carries from the source |
|---|---|
| `owner` | The owner SID. |
| `dacl` | The whole DACL — every access rule on the file, inherited rules included. |
| `sacl` | The whole SACL — the audit rules and the integrity label. |
| `daclni` | The DACL with **inherited** rules stripped out — only the rules set explicitly on the source. |
| `saclni` | The SACL with inherited rules stripped out. |
| `timestamps` | The access and modification times. |
| `links` | The hard-link structure — files hard-linked together in the source stay hard-linked in the copy. |
| `exec` | Executable-ness: if the source has any POSIX execute bit, set all three execute bits on the destination; otherwise clear them. Symbolic links are skipped. This does not preserve each Unix mode bit separately. |
| `security` | Extended attributes whose names begin with `security.`, except `security.peios.sd`, which is handled through the descriptor components above. |
| `xattrs` | Extended attributes outside the `security.*` namespace. `xattr` is an alias. |

You rarely name those individually. These options select sensible sets:

| Option | Preserves |
|---|---|
| `-p` | `timestamps` and `exec`, both required. |
| `--preserve` | `timestamps` only. This differs from `-p`. |
| `--preserve=LIST` | The comma-separated attributes you name, with no implicit attributes. Other preservation options can add or remove attributes. |
| `--preserve-all` | Every supported attribute in the table above, including `exec`. The full DACL/SACL selections take precedence over their inherited-rule-stripping variants. |
| `--sd` | `owner`, `dacl`, `sacl`, including inherited ACL entries. The descriptor's group component is not selected. |
| `--sd-explicit` | `owner`, `daclni`, `saclni` — the owner and the source's **explicitly set** ACL rules. The group component is not selected. |
| `--no-preserve=LIST` | Turns the named attributes back *off* — useful to subtract from a broader option. |

With no explicit preservation list, a plain copy preserves `exec` **best-effort**: failure to carry executable-ness does not fail the copy. An explicit `--preserve=LIST` starts with no implicit attributes, so include `exec` if you need it. Bare `--preserve` uses the list `timestamps` and likewise does not select `exec`. In contrast, `-p`, `-a`, and an explicit `--preserve=exec` require it. These distinctions come from the [option defaults](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uucore/src/lib/features/preserve.rs#L172-L235) and [`cp`'s bare-option parsing](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uu/cp/src/cp.rs#L576-L594); the [exec handler](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uucore/src/lib/features/preserve.rs#L842-L861) implements the execute-bit conversion.

Preservation options combine in command-line order: requests add attributes, `--no-preserve` removes them, and `-a` or `--preserve-all` selects the full supported set again. For example, `-a --no-preserve=exec` removes executable-ness from the archive request. See the [resolver](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uucore/src/lib/features/preserve.rs#L412-L441).

The `security` selection is broader than `security.peios.*`: it can include compatibility attributes such as `security.capability` if present and readable. `xattrs` does not include that namespace. The [attribute filters](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uucore/src/lib/features/preserve.rs#L730-L750) exclude `security.peios.sd` from both classes, so copying extended attributes cannot fill in descriptor components omitted by the SD copy.

### `--sd` versus `--sd-explicit`

Both select the source's owner, DACL, and SACL; they differ in how they treat *inherited* rules.

- **`--sd`** passes the owner and the whole source DACL and SACL, including inherited entries, to the destination's descriptor-setting operation.
- **`--sd-explicit`** carries the owner but strips inherited entries from the source ACLs before applying them, letting the destination directory supply inheritance. Use it when copying a file into a *different* directory and you want the file's own tailored rules to come along while still picking up the new location's inherited rules.

**Neither option selects the descriptor's `GROUP` component.** The [copy implementation selects only `OWNER`, `DACL`, and `SACL`](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uucore/src/lib/features/preserve.rs#L866-L926); it does not request replacement of the destination's group from the source. There is no `group` preservation attribute. The same limit applies to `-a` and `--preserve-all`. These options are not a promise of a byte-identical descriptor or preservation of every descriptor control bit, and do not establish a complete security backup/restore procedure.

For what "inherited" versus "explicit" means, see [Inheritance](~peios/security-descriptors/inheritance).

### When a preserve cannot be honoured

A requested preserve is a firm instruction. If `cp` cannot carry an attribute across — for example, writing the copy's SACL requires the `SeSecurityPrivilege` privilege, and the caller does not have it — `cp` treats that as a hard error and reports failure. This includes required `exec` preservation, unlike the best-effort executable-ness of a plain copy.

**Failure is not a rollback.** Destination files or a partially copied tree may already exist when a preserve fails; the [regular-file error path even attempts to truncate the destination](https://github.com/peios/peiosutils/blob/3344d4690476fd66bfaec99b1ae92190bbcba06f/src/uu/cp/src/cp.rs#L1947-L1968). Treat that output as incomplete; do not delete the source or replace a known-good backup on the strength of a partial copy. Check the exit status and verify the content and each attribute you require before relying on the result.

There is one exception, and it is a matter of definition rather than a softening of the rule. `security` and `xattrs` name extended attributes, and some filesystems have no extended attributes **at all** — FAT, 9p, and a squashfs image built without an attribute table are the ones you will meet. Copying *from* such a filesystem carries nothing, because there was nothing there: the preserve is satisfied vacuously, and the copy succeeds.

That is narrow on purpose. It applies only to reading the source. If the source does have extended attributes and the *destination* filesystem cannot hold them, the preserve genuinely failed and `cp` still stops:

```
# cp -a /home/jack/notes /mnt/usb-fat/
cp: failed to set extended attributes on '/mnt/usb-fat/notes': Operation not supported
```

The distinction matters most for `-a`, which requests both attribute classes on every file it touches. Without it, one xattr-less filesystem anywhere in a tree would abort the whole copy partway through.

## Overwriting an existing destination

By default, if the destination already exists, `cp` overwrites it. These options change that.

| Option | Effect |
|---|---|
| `-i`, `--interactive` | Ask before overwriting an existing file. |
| `-n`, `--no-clobber` | Never overwrite an existing file; skip it silently. |
| `-u`, `--update[=WHICH]` | Overwrite only when the source is newer than the destination. `WHICH` can be `all`, `none`, or `older`. |
| `-f`, `--force` | If an existing destination cannot be opened for writing, remove it and try the copy again. |
| `--remove-destination` | Remove the destination *before* opening it, always — contrast `--force`, which only removes on failure. |
| `-b`, `--backup[=CONTROL]` | Before overwriting, make a backup of the destination. |

A backup is refused when making it would destroy the source: if the source *is* the file the destination's backup would be written over (for example `cp --backup=simple a~ a`), `cp` stops with an error instead of overwriting it. The check compares file identity, not spelling.

## Symbolic links in the source

When a source is a symbolic link, `cp` can copy the link itself or the file it points to.

| Option | Effect |
|---|---|
| `-L`, `--dereference` | Always follow symbolic links — copy the file they point to. |
| `-P`, `--no-dereference` | Never follow symbolic links — copy the link itself. |
| `-H` | Follow only the symbolic links named directly on the command line, not links found while recursing. |
| `-d` | Copy symbolic links as links, and preserve hard-link structure. |

## Other ways to copy

`cp` can also produce something other than a plain duplicate.

| Option | Effect |
|---|---|
| `-l`, `--link` | Create a hard link to the source instead of copying its data. |
| `-s`, `--symbolic-link` | Create a symbolic link to the source instead of copying. |
| `--reflink[=WHEN]` | Make a lightweight copy-on-write clone where the file system supports it. `WHEN` is `always`, `auto`, or `never`. |
| `--sparse[=WHEN]` | Control whether runs of zero bytes are stored as holes rather than written out. `WHEN` is `always`, `auto`, or `never`. |
| `--attributes-only` | Create the destination and copy its attributes, but not its data. |

## Other options

| Option | Effect |
|---|---|
| `-t`, `--target-directory=DIR` | Copy every source into `DIR`. Useful when the directory is not the last argument. |
| `-T`, `--no-target-directory` | Treat `dest` as a plain file even if it is a directory. |
| `--parents` | Recreate the source's leading directories under the destination. |
| `-x`, `--one-file-system` | Do not cross into a different file system while recursing. |
| `--strip-trailing-slashes` | Strip any trailing slashes from each source argument before using it. |
| `-v`, `--verbose` | Print each file as it is copied. |
| `--debug` | Explain in detail how each file was copied. Implies `-v`. |
| `--progress` | Show a progress bar. |

## Exit status

| Code | Meaning |
|---|---|
| `0` | Every file was copied successfully. |
| `1` | A file could not be copied — including a requested `--preserve` that could not be honoured. |
